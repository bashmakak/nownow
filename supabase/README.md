# База данных и вход: что настроено и что осталось сделать

Проект Supabase называется `nownow`, регион — Франкфурт (`eu-central-1`), тариф бесплатный.
Адрес проекта и публикуемый ключ записаны в `src/config.js`.

## Что уже сделано

- Созданы таблицы `progress` и `profiles`, включены правила доступа: каждый видит только свою строку
  (файл `migrations/20261007041647_accounts_and_progress.sql`).
- Правила проверены на двух придуманных пользователях: чужое не читается и не меняется, без входа
  таблицы недоступны. Проверку можно повторить в любой момент файлом `check_access.sql`.
- Встроенная проверка безопасности Supabase (Advisors → Security) замечаний не показала.

## Что нужно сделать в панели Supabase

Панель: https://supabase.com/dashboard → проект `nownow`. Шаги 1 и 2 обязательны, без них
регистрация для посетителей не работает.

### 1. Адрес сайта

Authentication → URL Configuration.

- **Site URL:** `https://bashmakak.github.io/nownow/`
- **Redirect URLs:** добавить `https://bashmakak.github.io/nownow/`
  (для проверки на своём компьютере — ещё `http://localhost:5173/`).

Зачем: на этот адрес ведут ссылки из писем. Пока там стоит `http://localhost:3000`, ссылка
«подтвердить адрес» открывает пустую страницу, а «сбросить пароль» не работает совсем.
Указывайте точный адрес, без звёздочек: тогда ссылку из письма нельзя направить на чужой сайт.

### 2. Отправка писем

Authentication → Emails → SMTP Settings.

Встроенная почта Supabase предназначена для проверки: она отправляет письма только на адреса
участников вашей организации в Supabase, и число писем в час сильно ограничено. Посетитель с другим
адресом при регистрации получит отказ. Чтобы письма уходили всем, подключите почтовый сервис
(например, Resend, Brevo, Mailgun или Postmark) и впишите его данные в этой форме.
Понадобится свой домен: с него будут отправляться письма.

Пароль и ключ почтового сервиса вводятся только в панели Supabase. В репозиторий и в файлы сайта
они не попадают никогда.

### 3. Письма на русском

Authentication → Emails → Templates. По умолчанию письма на английском и без оформления.
Готовые шаблоны в стиле сайта лежат в папке `emails`:

| Шаблон в панели | Тема письма (поле Subject) | Файл |
| --- | --- | --- |
| Confirm sign up | `Подтвердите адрес почты — NowNow` | `emails/confirm-signup.html` |
| Reset password | `Смена пароля — NowNow` | `emails/reset-password.html` |
| Password changed (необязательно) | `Пароль изменён — NowNow` | `emails/password-changed.html` |

Откройте файл, скопируйте его целиком, вставьте в поле текста шаблона вместо того, что там есть,
впишите тему и сохраните. Остальные шаблоны (Invite user, Magic link, Change email address,
Reauthentication) сайт не использует: их можно не трогать.

Ссылка в этих письмах ведёт сразу на сайт: `{{ .SiteURL }}?token_hash=…`. Это сделано намеренно:

- человек видит в письме адрес сайта, а не служебный адрес Supabase;
- почтовые антивирусы, которые заранее открывают ссылки из писем, не «сжигают» одноразовую ссылку:
  она срабатывает, только когда страницу открыл сам человек;
- ссылка работает на любом устройстве, а не только там, где регистрировались.

Поэтому шаблоны зависят от шага 1: в Site URL должен стоять адрес сайта со слэшем на конце.
Письма со стандартной ссылкой Supabase (`{{ .ConfirmationURL }}`) сайт тоже понимает.

«Password changed» — уведомление о том, что пароль сменили. Оно относится к группе Security
в том же разделе и по умолчанию выключено: письмо уходит, только если уведомление включить.
С ним человек сразу узнает, если пароль сменил кто-то другой, и сможет вернуть доступ по кнопке в письме.

Если подключите почтовый сервис с отслеживанием переходов по ссылкам (click tracking), выключите
эту функцию: она подменяет ссылки в письмах, и подтверждение перестаёт работать.

Шаблоны проверены в браузере в светлой и тёмной теме и на ширине телефона. В почтовых программах
вёрстка может немного отличаться: например, Outlook для Windows рисует кнопку прямоугольной.

### 4. Требования к паролю

Authentication → Sign In / Providers → Email.

- **Confirm email** оставить включённым: без подтверждения можно зарегистрироваться на чужой адрес.
- **Minimum password length:** 8. Сайт уже требует 8 знаков, но проверка в самой базе надёжнее.

Не включайте без доработки сайта: «Require current password when changing password», CAPTCHA
(Authentication → Attack Protection) и вход через другие сервисы. Форма сайта их пока не поддерживает,
и вход перестанет работать.

### 5. Удаление учётной записи одной кнопкой

SQL Editor → вставить файл `delete_account.sql` целиком → Run.

Пока функция не создана, кнопка «Удалить учётную запись» работает как заявка: прогресс человека
в облаке стирается сразу, а запись с адресом почты нужно удалить вручную (см. ниже).
После создания функции запись удаляется сразу. Сайт менять не нужно.

### 6. Сведения о владельце сайта

Файл `src/data/legal.js`: имя или название, страна, адрес для обращений. Пока они пустые,
соглашение и политика конфиденциальности показывают пометку «Черновик».

## Заявки на удаление (пока не выполнен шаг 5)

Посмотреть заявки: SQL Editor →

```sql
select user_id, state ->> 'deleteRequested' as requested_at
from public.progress
where state ? 'deleteRequested';
```

Удалить запись: Authentication → Users → найти пользователя по идентификатору → Delete user.
Вместе с ним удалятся его прогресс и отметка о согласии.

## Чего здесь нельзя делать

- Не копируйте в репозиторий, в переписку и в файлы сайта секретный ключ (`sb_secret_…`), ключ
  `service_role`, пароль базы и строку подключения. Сайту они не нужны. Если ключ куда-то попал —
  отзовите его: Settings → API Keys.
- Не отключайте Row Level Security у таблиц и не добавляйте правила «разрешить всем».
  После любого изменения схемы запускайте `check_access.sql` и смотрите Advisors → Security.
- Не выгружайте таблицу пользователей в файлы внутри папки проекта.

## Что стоит знать о бесплатном тарифе

- Проект, к которому неделю почти не обращались, Supabase ставит на паузу. Перед этим на почту
  владельца приходит предупреждение. Возобновить проект можно в панели в течение 90 дней.
  Пока проект на паузе, вход и синхронизация на сайте не работают, а уроки и прогресс в браузере — работают.
- Защита от утёкших паролей доступна только на платном тарифе.
