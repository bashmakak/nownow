# NowNow

Сайт быстрых знаний: один урок даёт одно ключевое знание за несколько минут.
У урока может быть две версии, короткая и полная. Время каждой считается по её тексту и показано на карточке.

Это демо-версия. Сайт — статические файлы: своего сервера у него нет. Прогресс, закладки и заметки
хранятся в браузере посетителя. Если человек создал учётную запись, копия прогресса лежит в базе
Supabase и появляется на других его устройствах. В той же базе лежат уроки, которые написали участники.

## Что внутри

- Главная страница, каталог из 74 уроков по 33 темам в пяти разделах, страницы тем и уроков.
- Плеер урока из шести блоков: зачем, идея, пример, практика, проверка, ключевое знание.
- Интерактивные задания внутри уроков по искусственному интеллекту и маршрут по этой теме.
- Тренажёры: шесть наборов по ИИ, вопросы по любой теме каталога и повторение пройденного.
- Мини-игры на внимание, реакцию, память и счёт: восемь игр.
- Интересы: человек отмечает темы и навыки, по ним собираются тренировка дня из трёх раундов
  и подборка уроков «Для вас».
- Опыт, уровни, серия дней и достижения.
- Кабинет: продолжить урок, уровень и достижения, статистика, карточки ключевых знаний, заметки, выбор темы оформления.
- Учётные записи (необязательные): регистрация, вход, восстановление пароля, синхронизация прогресса,
  выгрузка своих данных, удаление учётной записи.
- Авторские уроки: мастерская с редактором, проверка модератором перед публикацией, вкладка «От авторов»
  в каталоге, жалобы читателей и искры — внутренние очки за опубликованные и пройденные уроки.
- Пользовательское соглашение, политика конфиденциальности, уведомление о хранении данных в браузере.

## Запуск на своём компьютере

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev      # сайт откроется на http://localhost:5173
npm run build    # готовая сборка появится в папке dist
npm test         # проверка правил слияния прогресса между устройствами
npm run check    # проверка, что в файлах нет секретов и чужих данных (сборка запускает её сама)
```

## Учётные записи и база данных

Учётная запись необязательна: без неё сайт работает так же, а прогресс хранится в браузере.
Вход — по адресу почты и паролю через [Supabase](https://supabase.com). Что нужно настроить
в панели Supabase, чтобы регистрация заработала для всех, описано в [`supabase/README.md`](supabase/README.md).

Как это устроено:

- **Пароли.** Пароль уходит из формы прямо в службу входа Supabase по HTTPS. Сайт его не хранит.
  В базе лежит только хеш, по которому пароль не восстановить.
- **Данные.** Для учётных записей в базе две таблицы. `progress` — одна строка на человека, весь прогресс
  одним документом. `profiles` — отметка о том, с какими редакциями документов человек согласился при регистрации.
  Таблицы авторских уроков описаны в своём разделе ниже.
- **Доступ.** Правила заданы в самой базе (`supabase/migrations`): без входа таблицы недоступны,
  после входа человек читает и меняет только свою строку. Проверить это можно файлом `supabase/check_access.sql`.
- **Синхронизация** (`src/lib/sync.js`). Сайт забирает строку из базы, сводит её с тем, что в браузере
  (`src/lib/merge.js`), и записывает итог обратно. Прогресс, набранный до входа, переносится в учётную запись.
  Если с двух устройств пишут одновременно, второе замечает это по номеру версии и сводит данные заново.
- **Выход.** Прогресс остаётся в учётной записи, а из браузера стирается: компьютер может быть общим.
- **Ссылки из писем.** По ссылке подтверждения сайт входит сам, только если регистрацию начинали в этом же
  браузере. Иначе просит пароль: так чужая ссылка не затянет человека в чужую учётную запись.
- **Без Supabase.** Если в `.env.local` задать пустой `VITE_SUPABASE_URL`, учётные записи отключаются,
  и сайт работает полностью в браузере.

Библиотека Supabase скачивается только тем, кто входит в учётную запись.

## Авторские уроки, модерация и искры

Любой участник с учётной записью может написать урок. Урок выходит в каталоге только после решения модератора.

### Путь урока

1. **Мастерская** (`/studio`). Человек выбирает имя автора — оно будет видно рядом с уроками — и принимает
   правила для авторов. Редактор повторяет формат сайта: шесть блоков, три вопроса, карточка итога,
   от 2 до 9 минут по расчёту. Черновик сохраняется сам. Редактор показывает, чего не хватает,
   и не даёт отправить незаполненный урок.
2. **Проверка** (`/moderation`). Модератор читает урок целиком и либо публикует его, либо возвращает
   с комментарием. Комментарий при возврате обязателен. Пока урок на проверке, автор не может его править —
   только отозвать.
3. **Публикация.** Одобренная копия попадает в отдельную таблицу, и только её видят читатели: вкладка
   «От авторов» в каталоге, страница урока, плеер. Урок помечен как авторский, имя автора указано.
4. **Правки.** Изменённый урок снова становится черновиком и проходит проверку заново. До нового решения
   на сайте остаётся прежняя версия.
5. **Жалобы и скрытие.** На странице авторского урока есть «Пожаловаться на урок» (нужен вход). Жалобы видит
   модератор; он может скрыть урок. Автор может снять свой урок с публикации и вернуть его, но урок,
   скрытый модератором, сам вернуть не может.

Модераторов назначает владелец сайта в базе данных — см. [`supabase/README.md`](supabase/README.md).
С сайта назначить модератора нельзя.

### Искры

Искры — внутренние очки, которыми отмечается вклад автора. Денежной стоимости у них нет.

| За что | Сколько |
| --- | --- |
| Урок прошёл проверку и опубликован (один раз за урок, повторное одобрение после правок не считается) | 50 |
| Вошедший читатель прошёл урок до конца (один раз за человека; автор за свой урок не получает) | 5 |
| Этот читатель отметил урок полезным | 2 |

Размеры заданы в базе, в функциях `review_lesson` и `complete_lesson`; подписи для интерфейса —
в `src/data/rules.js`. Авторские уроки бесплатны, как и остальные.

Сейчас искры нельзя потратить, передать или вывести: это счётчик. Так сделано намеренно. Выплаты авторам —
это уже деньги: нужны платёжный сервис, договор с автором, учёт налогов и проверка юристом, а на сайте
пока нет даже оплаты. Соглашение прямо говорит, что искры не дают права на выплату.

Куда это может развиваться, когда на сайте появится оплата (ничего из этого не сделано):

- **Тратить искры внутри сайта.** Например, менять их на месяцы подписки. Денег наружу не уходит,
  поэтому это самый простой следующий шаг.
- **Доля от подписки.** Часть выручки за месяц делится между авторами пропорционально прохождениям
  их уроков подписчиками. Журнал `ledger` и таблица `completions` уже хранят всё, что нужно для расчёта.
- **Платные уроки.** Автор назначает цену, сайт берёт комиссию. Это самый сложный вариант: возвраты,
  налоги, споры о качестве.

### Защита от накрутки

- Искры начисляют только функции базы. С сайта нельзя ни записать строку в журнал, ни одобрить урок,
  ни назначить себя модератором: у обычного пользователя на это нет прав.
- Прохождение засчитывается только вошедшему читателю и один раз за человека. Чтобы создать учётную
  запись, нужно подтвердить адрес почты.
- Не больше 30 новых засчитанных уроков в сутки с одной учётной записи.
- У автора не больше 50 уроков и не больше 5 одновременно на проверке.
- Сайт не проверяет, что человек действительно читал урок: функцию `complete_lesson` может вызвать
  любой вошедший пользователь. Пока искры ничего не стоят, это не страшно. Перед тем как привязывать
  к ним деньги или подписку, проверку нужно усилить: например, учитывать только подписчиков и время в уроке.

### Как это устроено в базе

Файл `supabase/migrations/20261007070817_community_lessons.sql`.

| Таблица | Что хранит | Кто видит |
| --- | --- | --- |
| `authors` | Имя автора и пара строк о себе | Все, если у автора есть опубликованный урок; иначе он сам и модераторы |
| `lesson_drafts` | Рабочая версия урока, статус, комментарий модератора | Автор; модераторы — только отправленное на проверку |
| `lessons_public` | Одобренная копия урока, счётчики прохождений | Все; скрытый урок — автор и модераторы |
| `moderators` | Кто может проверять уроки | Каждый видит только свою строку |
| `completions` | Кто прошёл какой урок | Только сам читатель |
| `ledger` | Журнал искр | Только автор |
| `reports` | Жалобы | Тот, кто пожаловался, и модераторы |

Правила доступа проверяются файлом `supabase/check_community.sql`: он проводит придуманный урок через весь
путь и пробует всё, чего делать нельзя.

### Как авторский урок попадает на сайт

Опубликованные уроки читаются простым запросом с публикуемым ключом: вход и библиотека Supabase для этого
не нужны (`src/lib/community.js`). Запрос уходит, только когда человек сам открыл вкладку «От авторов»
или авторский урок; обычному посетителю каталога сайт к базе не обращается. Список приходит без текстов,
текст урока скачивается при открытии. Всё полученное проходит через `cleanLesson`
(`src/lib/lesson-format.js`) и выводится только как текст: разметку и ссылки из чужого урока сайт не исполняет.

Прогресс по авторскому уроку хранится так же, как по любому другому, под его адресом (`u-…`).
Если урок потом сняли с публикации, прогресс и опыт у читателя остаются.

## Что нельзя класть в репозиторий

Репозиторий открытый, а сайт — файлы, которые видит любой посетитель. Поэтому здесь не должно быть:

- секретного ключа Supabase (`sb_secret_…`) и ключа `service_role`: они дают полный доступ в обход правил;
- пароля базы данных и строки подключения `postgres://…`;
- ключей почтового сервиса, токенов GitHub;
- файлов `.env` (в репозитории только образец `.env.example` без значений);
- адресов почты и паролей пользователей, в том числе тестовых. В примерах используйте `name@example.com`.

Сайту секретный ключ не нужен вообще: всё, что он делает, разрешено правилами доступа обычному вошедшему
пользователю. Адрес проекта и публикуемый ключ (`sb_publishable_…`) в `src/config.js` — открытые значения:
они и так видны в браузере каждого посетителя, данные защищают правила в базе.

Это проверяется автоматически: `scripts/check-secrets.mjs` просматривает файлы перед каждой сборкой
и готовую сборку после неё. Если что-то нашлось, сборка и публикация останавливаются.
`npm run check:history` проверяет всю историю коммитов.

Дополнительно стоит включить защиту на стороне GitHub: Settings → Code security → Secret scanning
и Push protection. Тогда GitHub сам не примет коммит с известным видом ключа.

## Документы

Пользовательское соглашение и политика конфиденциальности лежат в `src/pages/Legal.jsx`. Сведения
о владельце сайта (имя или название, страна, адрес для обращений) подставляются из `src/data/legal.js`.
Пока они не заполнены, оба документа показывают пометку «Черновик».

Тексты описывают то, что сайт делает на самом деле. Если меняется поведение сайта — появляется аналитика,
оплата, новый поставщик, — поправьте текст и дату редакции в `src/config.js` (`DOCS`). Дата попадает
в запись о согласии каждого нового пользователя.

Документы написаны как рабочая основа, а не как юридическое заключение. Перед открытием регистрации
для всех их стоит показать юристу, который знает право вашей страны: требования к обработке
персональных данных и к их хранению за рубежом в странах СНГ различаются.

## Версии урока

**Короткая** есть у каждого урока. В ней все шесть блоков: короткое вступление, список тезисов,
один пример, три шага практики, три вопроса. Занимает от 3 до 7 минут.
Образец: любой объект в `src/data/courses-d.js`.

**Полная** — те же шесть блоков, написанные подробно. Сейчас она есть у 33 уроков, по одному
в каждой теме: файлы лежат в `src/data/full/`, каждый назван по slug урока.
Полная версия занимает 20–24 минуты. От короткой она отличается тремя вещами:

- вместо коротких списков в блоках стоит поле `body` — массив узлов
  `["p", текст]`, `["h", заголовок]`, `["ul", [...]]`, `["ol", [...]]`, `["note", подпись, текст]`,
  `["think", вопрос, разбор]` (вопрос с раскрывающимся ответом), `["code", текст]`,
  `["quote", текст, автор]`, `["table", шапка, строки, подпись]`;
- в практике есть рабочий лист `sheet`: поля, которые читатель заполняет, ответы сохраняются
  и показываются в кабинете;
- вопросов на закрепление пять, а не три.

Внутри текста работают две пометки: `**жирный**` и `` `код` ``.

Чтобы добавить уроку полную версию, создайте в `src/data/full/` файл с именем slug урока
по образцу `psihologiya-prinyatiya-reshenij.js`. В нём `slug` и шесть блоков: `why`, `idea`,
`example`, `practice`, `check`, `key`. Можно добавить `sources`. Подключать файл нигде не нужно.

Текст полной версии не входит в основную сборку: браузер скачивает его, только когда урок
открывают в полной версии. Время, заголовки блоков и карточку итога сайт берёт из сводки
`src/data/full-meta.js`. Она создаётся сама перед `npm run dev` и `npm run build`
(скрипт `scripts/full-meta.mjs`), в репозитории её нет.

На странице урока появится выбор версии, на карточке — время обеих. Прогресс версий хранится отдельно.

## Интерактивные задания в уроках

Задание — это поле `play` в блоке урока (`why`, `idea`, `example` или `practice`). Плеер показывает его
после основного текста блока. Виды заданий и формат каждого описаны в начале `src/components/Play.jsx`:

| Вид | Что делает читатель |
| --- | --- |
| `pick` | выбирает лучший из двух-трёх вариантов |
| `sort` | раскладывает карточки по двум корзинам |
| `label` | относит фрагмент к одной из нескольких меток |
| `predict` | угадывает самое вероятное слово, потом видит условные проценты |
| `order` | расставляет шаги по порядку |
| `spot` | отмечает в тексте места, которые нужно найти |
| `temp` | двигает ползунок температуры и сравнивает ответы |
| `build` | собирает запрос из элементов и видит, чего не хватает |
| `window` | уменьшает контекстное окно и видит, что теряет модель |

Задание не обязательно: урок можно пройти и без него. Выполненное задание даёт 5 очков опыта.
Образцы: уроки в `src/data/courses-i.js`.

Порядок уроков темы задаёт `PATHS` в `src/data/index.js`. Если у темы есть маршрут, на её странице
появляется блок «Маршрут по теме», а карточки идут в том же порядке.

## Тренажёры

Тренажёр — набор однотипных заданий в `src/data/trainers.js`. Раунд берёт из набора восемь случайных
заданий (`ROUND`). Чтобы добавить тренажёр, допишите объект в массив `TRAINERS`: `id`, `topic`, `type`
(`pick`, `sort`, `label` или `predict`), `title`, `hook`, `ask`, `lesson` (урок, который он закрепляет)
и `items`. В наборе должно быть не меньше двенадцати заданий, иначе раунды будут повторяться.

- Очки: 100 за верный ответ, до 50 за скорость, до 50 за серию верных подряд (`points` в `src/lib/game.js`).
- Молнии: три за раунд без ошибок, две — от трёх четвертей верных, одна — от половины.
- «Повторение» собирает вопросы из проверок уроков, которые посетитель уже прошёл.
- «Вопросы по теме» есть у каждой темы каталога: раунд собирается из проверок её уроков
  (`topicPool` в `src/lib/game.js`). Отдельно писать задания не нужно: добавили урок — вопросов стало больше.
  Адрес раунда — `/train/t-<slug темы>`.
- «Тренировка дня» — три раунда: мини-игра, тема, повторение. Набор зависит от даты и от интересов
  (`dailyPlan`). День с тренировкой идёт в серию.

## Интересы

Человек отмечает, что ему интересно: темы каталога и навыки мини-игр. Выбрать можно на экране
«Проверьте почту» после регистрации, в кабинете и по подсказке на главной или в тренажёрах.
Учётная запись для этого не нужна: выбор хранится вместе с прогрессом (`interests` в `src/lib/store.js`),
а у вошедшего человека синхронизируется между устройствами.

От интересов зависят:

- тренировка дня: игра на выбранный навык и вопросы по выбранным темам;
- блок «Для вас» на главной: уроки выбранных тем, начатые первыми, без пройденных (`recommend`);
- раздел «По вашим темам» в тренажёрах, «Ваши темы» на странице тем, фильтр «Мои темы» в каталоге.

Если ничего не выбрано, сайт работает как раньше: в тренировке дня любая игра и тренажёры по ИИ.

## Мини-игры

Восемь игр в четырёх навыках: внимание (таблица Шульте, цвет и слово, лишний знак), реакция (реакция, сигнал),
память (матрица, ряд цифр), счёт (быстрый счёт). Описания, правила и пороги молний лежат в `src/data/brain.js`,
сами игры — в `src/pages/Brain.jsx`: этот файл скачивается, только когда человек открывает игру.

Чтобы добавить игру, опишите её в `GAMES` (`id` начинается с `g-`) и добавьте компонент в `Brain.jsx`
под тем же `id` в таблицу `PLAY`. Компонент сам ведёт раунд и в конце вызывает
`onDone({ raw, score, lines })`: `raw` — результат в своих единицах (секунды, клетки, очки), по нему
считаются молнии; `score` — очки для сравнения попыток.

- Молнии даются по порогам из поля `bolts`. Пороги подобраны так, чтобы отвечать наугад было невыгодно:
  ошибки и лишние нажатия отнимают очки.
- Опыта за игру вдвое меньше, чем за тренажёр: 5 и ещё по 5 за молнию. Он начисляется за первый раунд
  игры в день и за новый рекорд. Игра длится меньше минуты, и без этого правила опыт за уроки обесценился бы.
- Каждая игра работает с клавиатуры и на телефоне, игровое поле целиком помещается в экран.

Игры тренируют то, что в них делаешь. Исследования не подтверждают, что они улучшают мышление в целом,
и тексты сайта прямо говорят об этом. Не заменяйте эти формулировки обещаниями «развить мозг».

## Опыт, уровни, достижения

Правила лежат в `src/lib/game.js` (`XP`, `levelOf`, `ACHIEVEMENTS`):

- короткий урок — 40 очков опыта, полный — 100, каждый верный ответ проверки — 5, задание в уроке — 5;
- раунд в тренажёре — 10 и ещё по 10 за каждую молнию, выполненная тренировка дня — 30;
- раунд в мини-игре — 5 и ещё по 5 за каждую молнию, раз в день на игру или за новый рекорд;
- первый уровень длится 100 очков, каждый следующий на 50 длиннее.

Опыт за уроки не хранится, а считается по прогрессу, поэтому его получают и те, кто занимался
до появления наград. Рейтинга между посетителями нет: каждый видит только свои результаты.

## Как считается время

Статистики прохождений у сайта нет, поэтому время — оценка по тексту урока
(файл `src/data/timing.js`):

- чтение со скоростью 150 слов в минуту (`WPM`);
- 15 секунд на каждый вопрос проверки, 20 секунд на вопрос «остановитесь и подумайте»,
  60 секунд на каждое поле рабочего листа, 30 секунд на интерактивное задание (`PAUSE`).

Результат округляется до минут. Чтобы поменять допущения, исправьте `WPM` и `PAUSE`:
время на всём сайте пересчитается само. Когда появятся данные о реальных прохождениях,
оценку стоит заменить средним по ним.

## Принятые решения

- Регион запуска: страны СНГ, язык русский. В уроках нет привязки к законам и валюте одной страны:
  суммы даны без названия валюты, уроки о праве учат навыку, а не нормам, и отсылают к местному закону.
- Монетизация: предварительно подписка. На сайте её пока нет.
- Авторские уроки публикуются только после проверки модератором. Авторы получают искры — внутренние очки
  без денежной стоимости; выплат нет и они не обещаны. Что делать с искрами дальше, решается вместе с оплатой.
- Учётная запись необязательна. Она нужна только для переноса прогресса между устройствами;
  уроки, задания и тренажёры доступны без неё. Минимальный возраст для регистрации — 18 лет.
- Аналитики, рекламы и файлов cookie на сайте нет. Уведомление о хранении данных только сообщает,
  что лежит в браузере: выбирать посетителю нечего.
- Игровые элементы сделаны по образцу тренажёров для ума. Тренажёры проверяют материал уроков, мини-игры —
  внимание, реакцию, память и счёт. Мини-игры — разминка, а не замена урокам, и обещаний «стать умнее»
  на сайте нет. Тон взрослый: молнии вместо звёзд, без персонажей и шуток.
- Концепция: быстрые знания. Обещания «30 минут» больше нет: у каждого урока своё время,
  посчитанное по тексту, и выбор между короткой и полной версией.
